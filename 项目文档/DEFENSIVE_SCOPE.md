# TraceMeadow 防御用途与本轮复核范围

复核日期：2026-10-02。

## 实际防御用途

解释有权限收集的本地 Darwin kdebug 数据，按时间、线程、进程和调用栈调查异常与故障。

## 实际能力

CLI 接收本地二进制流，handlers 中的 syscall 名称用于解释已有事件。日志可能包含路径、进程、线程和其他敏感元数据；输出没有自动全面脱敏保证。

## 当前检查

1.0.2 已实质重写有界读取、v2/v3 分帧、元数据检查、trace-code 文本/文件读取及 CLI 输入与输出消费。修复缺失标记的 EOF 循环、截断事件的静默接受、零值时间戳被误认为填充等问题；CLI 错误返回 2，超限或部分结果明确不完整。输入阶段 435 项测试通过，其中新增 356 项边界测试；上游 69 项测试通过。输入阶段 1133 项对照中 1073 项一致、60 项无效输入错误有明确验证的差异。详细证据见 VALIDATION.md 与 CURRENT_VALIDATION.json。

事件解释和 handlers 全部源码已做范围核对；大型事件目录、其他 handlers 状态与格式化算法仍保留上游实现，尚未全部实质重写；1.0.3 的组状态与调用栈改写见下文。没有主动收集系统轨迹或执行记录中的 syscall。依赖与记录中的 socket/syscall 名称不能单凭名称认定为联网或执行行为。

## 验证边界

只共享已获准披露并完成脱敏的日志。输出没有全面脱敏或终端控制字符转义保证。输入字节、块、线程、事件、元数据层数和输出有明确默认上限；调用方流或持续写入的 stdin 仍可能等待，不是所有 handlers 状态的完整上限。v2 填充改为明确指定，正数 count 只验证所选前缀。实时 tracing、其他 Darwin 格式、真实设备及所有畸形流仍未证明。

## 1.0.3 聚合与调用栈迭代

事件聚合和调用栈映射已进一步实质重写，增加待完成组、存储引用、组内事件、帧/镜像/轨迹和 vnode 路径限额；组状态修改前先检查，已完成的空线程组及时释放。当前总计 459 项测试通过；1233 项来源对照包含 1173 项一致与原有 60 项明确错误变化，新增 100 项成功对照专门覆盖组序列和帧映射。调用栈的最近镜像基址推断仍无镜像跨度证明，未闭合组、其他 handlers 的状态与格式化仍待继续改写。旧 1.0.2 包不含这轮变化。
